# Relatório HCW-02-010 — adaptadores Gemini Live, Gemini texto e Ollama

- Data: 2026-11-22
- Estado: **GO**
- Fase: 2 — LLM Gateway com política de egress
- Dependências concluídas: `HCW-02-006`, `HCW-02-007`, `HCW-02-009`

## Objectivo

Criar adaptadores finos para Gemini texto, Ollama e sessão live usando apenas os contratos do gateway e a política de egress, sem SDK externo, sem endpoints inventados e sem contacto com fornecedores por omissão.

## O que foi entregue

- `app/llm/providers/common.py` — porta `ModelProvider`, validação de endpoint e adaptador, corpo interno do pedido, transporte `EgressPolicy.send_json`, classificação de falhas HTTP/rede/timeout e normalização da resposta.
- `app/llm/providers/gemini_text.py` — `GeminiTextProvider`, com chave opcional em `SecretStr` e cabeçalho `Authorization` mantido fora dos logs.
- `app/llm/providers/ollama.py` — `OllamaProvider` para o mesmo contrato HTTP interno.
- `app/llm/providers/gemini_live.py` — `LiveSession` como `Protocol`, `LiveSessionUnavailable` e fábrica `create_live_session` protegida por consentimento e autorização de egress.
- `app/llm/providers/__init__.py` — API pública do módulo.
- `app/llm/providers/README.txt` e `app/llm/providers/module.yaml` — documentação e metadados de guarda.
- `tests/unit/test_providers.py` — 7 testes com servidor HTTP falso, redacção, timeout, consentimento, resposta inválida, protocolo de sessão e ausência de import de SDK externo.
- `tests/integration/test_llm_real.py` — 2 testes opcionais, ignorados por omissão e activados apenas por `HCW_GEMINI_TEXT_ENDPOINT` / `HCW_OLLAMA_ENDPOINT`.
- `app/llm/README.txt`, `app/llm/module.yaml` e `docs/MAP.md` — actualizados para incluir `providers`.

## Decisões e desvios

- **Desvio planeado:** `app/llm/providers/common.py` foi adicionado a `files_new` em `tasks.yaml`. Centraliza transporte, classificação de erro e validação de resposta, evitando duplicação nos dois adaptadores HTTP.
- **Endpoint:** nenhum endereço é inventado. O chamador fornece o endpoint HTTP(S) completo por configuração/construtor.
- **Formato de fio:** o gateway usa o seu próprio JSON interno (`model`, `prompt`, `task_id`, `correlation_id`; resposta `text`, `tokens_used`). Não é uma emulação de API externa.
- **Voz:** a sessão real não é criada. `create_live_session` valida endpoint, exige `allows_cloud() is True`, chama `egress.authorize` e depois levanta `LiveSessionUnavailable` enquanto a dependência de voz não for aprovada.
- **Dependências:** nenhuma instalada; nenhum import de `litellm`, `google.genai`, `ollama` ou `requests`.

## Limitações

- O formato HTTP é o contrato interno do gateway; integração real com endpoints de fornecedores exigirá trabalho futuro e aprovação.
- `LiveSession` é apenas a porta; não existe dependência de voz aprovada na Fase 2.
- Testes reais dependem de configuração externa e credenciais geridas pelo Utilizador; nunca são executados automaticamente no CI desta fase.
